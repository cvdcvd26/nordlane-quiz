ГДЕ РАЗМЕСТИТЬ NORDLANE QUIZ
Обновлено 30 октября 2026: подтверждение задания сохраняется мгновенно вместе с заданием, без фоновой задержки.

РЕКОМЕНДУЕМЫЙ ВАРИАНТ: VERCEL + NEON + PRIVATE VERCEL BLOB + VERCEL QUEUES

Это приложение Next.js с серверными API, базой, загрузками и админкой. Для полной работы нужен Node.js-хостинг. Загрузка ZIP на статический хостинг, GitHub Pages или обычный PHP-хостинг не запустит серверную часть.

Vercel запускает сайт и API. Neon хранит контакты, ответы, переписки и настройки. Private Vercel Blob хранит файлы. Автоподтверждение записывается в той же транзакции, что и задание. Очереди сохранены только для старых незавершённых отправок; отдельный аккаунт Upstash для новых подтверждений не нужен.
GitHub в этой схеме хранит исходники; сам сайт работает на Vercel.

ПОРЯДОК ДЕЙСТВИЙ НА VERCEL
1. Распаковать архив. Поместить содержимое папки nordlane-quiz в Git-репозиторий. package.json должен находиться в корне выбранного проекта. Не загружать .env.local, node_modules, .next и локальные пользовательские файлы.
2. Vercel → New Project → импортировать репозиторий. Framework: Next.js. Node.js: 24. Install Command: npm ci. Build Command: npm run vercel-build. Output Directory: настройка Next.js по умолчанию.
3. Подключить PostgreSQL, предпочтительно Neon. Добавить DATABASE_URL. Для миграций добавить DATABASE_URL_UNPOOLED — прямой URL Neon без pooler. Скрипт vercel-build применяет миграции перед сборкой.
4. Создать PRIVATE Vercel Blob store и подключить BLOB_READ_WRITE_TOKEN. Публичное хранилище этому проекту не подходит.
5. Новые подтверждения не требуют очереди: успешный POST /api/submit возвращает уже сохранённое сообщение. На этапе «Готово» оно показывается сразу. Прежний queue-trigger и авторизация сохранены для завершения старых pending-заданий.
6. Добавить ADMIN_SESSION_SECRET и CRON_SECRET: два разных случайных секрета. Генерировать каждый отдельно: openssl rand -hex 32.
7. Добавить ADMIN_EMAIL и временный ADMIN_PASSWORD: от 10 символов, максимум 72 байта UTF-8. После первого входа в /admin удалить ADMIN_PASSWORD из настроек окружения и сменить пароль в админке.
8. Разделять production и preview; для preview использовать отдельную базу. Новые подтверждения не требуют APP_URL или QStash. Только для завершения исторических pending-заданий на другом Node.js-хостинге сохранить ключи QStash и APP_URL — полный origin без пути и параметров; подписанный callback должен быть доступен по сети.
9. Развернуть проект. Проверить: контакты → вопросы → загрузка → отправка задания → вход в /admin → ответ в чат → автоматическое сообщение. Реальные подключения к облачным сервисам необходимо проверить после размещения.

Все переменные перечислены в .env.example. Реальные секреты записываются в настройки хостинга; их нельзя помещать в public/ или переменные NEXT_PUBLIC_*.

АЛЬТЕРНАТИВА: RENDER WEB SERVICE
Render поддерживает Next.js как Node.js Web Service. Выбирать именно Web Service, а не Static Site.
- Node.js 24.
- Build Command: npm ci && npm run db:migrate && npm run build
- Start Command: npm start
- Добавить те же настройки администратора и базы; очередь нужна только для исторических pending-заданий.
- Для базы подходят Neon или Render Postgres. Код теперь выбирает обычный PostgreSQL-драйвер для хостов вне Neon. При нестандартном прокси можно явно задать DATABASE_DRIVER=postgres либо neon.
- Для файлов: private Blob либо постоянный диск с UPLOAD_DIR=/var/data/uploads. Без Blob или постоянного каталога файлы не сохранятся надёжно; production-запись на случайный временный диск теперь запрещена.
- APP_URL=https://имя-сервиса.onrender.com либо ваш домен.
- vercel.json на Render не запускается. Для резервной доставки настроить внешний запрос GET /api/jobs/sweep с Authorization: Bearer <CRON_SECRET>. Это требуется только для исторических отложенных заданий; новые подтверждения сохраняются синхронно.

АЛЬТЕРНАТИВА: СОБСТВЕННЫЙ VPS
Нужны Node.js 24, PostgreSQL, HTTPS через reverse proxy, постоянное файловое хранилище, управление процессом приложения и резервные копии.
Команды после настройки .env.local:
  npm ci
  npm run db:migrate
  npm run build
  npm start
Процесс запускать через systemd или другой менеджер процессов. UPLOAD_DIR должен указывать на постоянный каталог с правами записи для пользователя приложения. Для нескольких экземпляров приложения использовать общее объектное хранилище. Прокси должен корректно выставлять Host, X-Forwarded-Proto и X-Forwarded-For.

ОБНОВЛЕНИЕ УЖЕ РАБОТАЮЩЕГО САЙТА
Добавлена миграция drizzle/0004_message_sequence.sql. Сначала сделать резервную копию базы. На время обновления остановить старые экземпляры, применить миграции и запустить новую версию. Миграция сохраняет старые сообщения и назначает им последовательные номера. Одновременная работа старого и нового кода не проверялась и не рекомендуется: старые обработчики не берут новую блокировку сессии.

ОГРАНИЧЕНИЯ
- В проекте остаются демонстрационные тексты, отзывы-примеры и PDF-заглушка; заменить перед публичным запуском.
- Поисковая индексация сейчас отключена намеренной настройкой демонстрационного проекта. Если нужен поисковый трафик, согласовать её включение для публичной страницы.
- Ежедневный cron в vercel.json — резервный механизм только для исторических отложенных заданий. Новое подтверждение не зависит от cron или внешнего планировщика.
- Админские пароли длиннее 72 байт теперь отклоняются, чтобы исключить незаметное усечение bcrypt. Если в существующей базе использовался такой пароль, сбросить его через scripts/create-admin.ts до обновления.
